# Congruence Eye: feature test matrix

This matrix maps every feature in the client's Tango Eye documents (the parity table T1–P1 in
`API_CONTRACT_V2.md`) and every feature in the v1 contract (`API_CONTRACT.md`) to the Congruence Eye screen that
implements it and to the Playwright test(s) that exercise it. The tests run against the real stack:

- a NestJS backend on a fresh, seeded SQLite database;
- the production Angular build;
- the Python ai-service API;
- the ai-service simulator (today plus a full day yesterday), followed by a generated recap video.

Spec files live in `e2e/tests/`. Test titles are quoted exactly so that `npx playwright test -g "<title>"` finds
them.

**Status** is the result of the final two runs of `scripts/run-all-tests.sh` (2026-10-05; both runs passed all 92 Playwright tests with 0 retries). PASS means the test passed
in both runs. PASS (retry) means it failed once and then passed on its automatic retry (retries = 1).

## 3. What the sandbox cannot exercise

| Area | Why | What is tested instead |
|---|---|---|
| SQL Server 2022 (`DB_TYPE=mssql`) | No SQL Server in the sandbox | The same TypeORM code on SQLite. The DDL is generated from the entities (`database/01_schema.sql`). |
| Real RTSP cameras / YOLO on live video | No cameras or NVR | The simulator renders CCTV-like frames through the same processor, AI Manager, spool and client. The ai-service pytest covers the YOLO model on a still image. Recorder connection tests run against the repo's real RTSP test server (edge-recorders.spec). |
| SMTP email and webhook delivery | No mail server | The EMAIL channel and recipients are stored and asserted. In-app notifications and SSE are tested end to end. |
| H.264 playback in the browser | Playwright's open-source Chromium has no H.264 decoder | The recap mp4 is checked with ffmpeg (h264, yuv420p, 1280 wide, +faststart, duration). The `<video>` element then plays a VP8 copy with the same frames and duration (`e2e/support/video.ts`). |
| Cron timing (nudges every 5 min, recap at 23:45, minute alert evaluation) | `DISABLE_CRON=true` keeps the suite deterministic | The same code paths run through the explicit endpoints: nudges/run, recaps/generate and alerts/evaluate. |
